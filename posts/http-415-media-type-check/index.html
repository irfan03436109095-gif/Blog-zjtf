HTTP 415 是机场拦截吗？先查请求格式与 Content-Type

酌酒听风2026-10-15— 次阅读
协议与网络

调用网站接口时返回 415 Unsupported Media Type，说明已经收到了 HTTP 响应，不能仅凭这个数字判断机场线路断了。RFC 9110 说明，服务器可能因请求的 Content-Type、Content-Encoding 或实际正文格式不被该资源支持而拒绝处理。

先保留三份证据

保存请求方法与路径、请求头里实际发送的 Content-Type 和 Content-Encoding、响应状态及响应头。保存前删除令牌、Cookie 和个人数据。仅把 Accept（希望接收的响应类型）改成 application/json，并不能自动修正发出的请求正文。

示意图：服务器依据目标接口要求检查请求格式；415 属于有响应的 HTTP 阶段。

按请求约定逐项核对

  1. 查看目标接口官方文档：它需要 JSON、表单还是上传文件？先确认方法、路径与正文格式。
  2. 对照实际请求：若发送 JSON，正文应是合法 JSON，Content-Type 也应与之对应；若使用 multipart/form-data，让客户端按上传方式构造边界，不要只手写一个媒体类型头。
  3. 若请求经过网关或代理，比较同一合法请求在两条路径上的状态、响应头和响应正文。不要把不同账号、不同接口或不同请求体当作网络对照。
  4. 若响应带 Accept 或 Accept-Encoding，结合 RFC 9110 的语境看服务器提示的是可接受媒体类型还是内容编码；最终仍以目标接口文档为准。

如果浏览器只是打开普通网页却出现 415，先核对是否点进了上传或 API 地址、页面是否触发了 POST 请求。不要盲目换节点、关闭证书验证，或反复重发含敏感内容的请求。

验收结果

在同一接口上，使用文档要求的正文和头信息后，415 不再出现，并能从实际响应确认操作结果，才算格式问题解决。状态变化为其他 4xx 时应按新状态继续处理。

可核验来源

  • RFC 9110：HTTP Semantics：Content-Type、内容编码和 415 的定义。核验日期：2026-10-15。
